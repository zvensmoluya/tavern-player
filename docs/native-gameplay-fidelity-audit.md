# Native 玩法还原验收

> 2026-09-05 开始。此文追踪当前 goal；此前的聊天实测是基础链路证据，不是复杂卡完整玩法验收。人工适配门槛尚未通过，自动编译尚未开始。本轮不改造 Tavern Shelf，也不要求 Player 依赖 Shelf。

## 验收方法

先记录原卡实际行为，再决定 Player 如何表达。每项区分原件中的确定性程序、交给模型判断的叙事规则、纯表现，以及已停用的代码。源码中的函数存在不证明其入口正在启用；提示词中的规则也不等于原运行环境有程序执行该规则。

验收需要证明用户的关键选择、可见信息、确定性规则与下一轮模型输入相符，且保存恢复、重试、候选切换不丢失或重复应用结果。`PARTIAL` 是总评，不能替代逐项缺失及影响。更改状态数据、生成新剧情、改写历史分别记录。

此前报告把“根据开局选择动态启停世界书”列为该卡明确缺失，证据不足，本次撤回。另一个纠正是：三个 alternate greetings 不都是正文开场，第三个是自定义开场说明。表单选择预设剧情仍会写身体和开局草稿；目前仅保留候选切换并不等于完整恢复了预设开场流程。

| P09 | 悬浮球 `bindDefeat`：未变身禁用；预览可取消；非空草稿不覆盖；确认后写战局与草稿，**不自动发送** | **未还原**：缺少受控的显式玩家操作生命周期 | 在不建立任意 action/trigger 的前提下实现；取消无变化，提交原子保存，恢复/重试不重复，下一轮能读取已提交选择 |
| P10 | `battleOf` 是显示修正；世界书要求变身与战局一致 | 显示修正尚未还原；跨字段关系仍交给模型，当前没有确定性保证 | 区分 UI 投影和事实状态；检验解除变身、重新变身与前一状态冲突，不把修正显示误报成修正状态 |
| P11 | 更新规则要求施法消耗、资源结算、关系变化及在场角色心里话 | 原规则作为上下文保留；原卡本身主要依赖模型判断 | 多轮无露骨内容的战斗/日常测试；记录模型遵循程度及需要本地机制的规则，不谎称全部已由代码执行 |
| P12 | UpdateVariable 显示正则只折叠原文，不结算状态；显示时钟不推进剧情时间 | 原始机器块保存在 sourceText，正文与状态分开；未复制显示时钟 | 提供足够可诊断的状态变化证据；不因去除显示外壳隐藏状态失败 |
| P13 | 字体、主题、拖拽位置、计数动画、定时渲染、iframe 卸载清理 | 交由 Player 原生表现和生命周期 | 固定 UI 简洁美观；这些表现变化不能掩盖 P07/P09 的信息及操作缺失 |
| P14 | 原输出格式提及 add/remove/move，但固定 19 路径的逐字段规则以 replace 为主并禁止扩展关系人 | 仅 scalar replace；其他操作整批拒绝 | 记录真实出现的操作和需求；不能据此宣称完整支持 MVU，也不能为不存在的需求先造通用 JSON Patch runtime |

没有证据表明这张卡的内嵌 JS 执行随机战斗结算。渲染计时器、MVU 等待和输入框延迟发送不是游戏回合规则。第二样本的随机图片选择必须单独记录，不能转述成此卡的随机战斗能力。

## 复用与编译门槛

《岁寒新正》继续验证已有的数值范围、阶段阈值、事件锁、消息资料面板及状态协议。尚缺对原卡全部分支、远程图片选择和长期剧情的验收。古茗医生作为无持久变量的表单回归，不能因为复杂卡需要状态协议而给它增添模型状态回写。

先解决 P01/P08/P09 等核心缺口并验证 P06/P10/P11。新增机制必须有独立于卡名、角色及数值的合成测试，再由真实卡验证语义。人工适配未过门槛前，不开始模型生成/修复内核。

通过后才推进：独立于 Shelf 的编译输入、来源证据、固定契约生成和确定性验证。使用额外未参与机制设计的卡，分别保存首次自动结果、自动修复结果及人工修改结果。若合理能力边界无法覆盖某项核心玩法，保存具体反例与产品取舍，不能把该项改成“视觉可降级”后通过验收。
