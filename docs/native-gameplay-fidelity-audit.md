# Native 玩法还原验收

> 2026-09-05 开始。此文追踪当前 goal；此前的聊天实测是基础链路证据，不是复杂卡完整玩法验收。人工适配门槛尚未通过，自动编译尚未开始。本轮不改造 Tavern Shelf，也不要求 Player 依赖 Shelf。

## 验收方法

先记录原卡实际行为，再决定 Player 如何表达。每项区分原件中的确定性程序、交给模型判断的叙事规则、纯表现，以及已停用的代码。源码中的函数存在不证明其入口正在启用；提示词中的规则也不等于原运行环境有程序执行该规则。

验收需要证明用户的关键选择、可见信息、确定性规则与下一轮模型输入相符，且保存恢复、重试、候选切换不丢失或重复应用结果。`PARTIAL` 是总评，不能替代逐项缺失及影响。更改状态数据、生成新剧情、改写历史分别记录。

## 显式玩家选择的本地验收

P09 已落入固定 `playerChoices` 流程，生产代码没有卡名判断或战败专用页面。原卡夹具声明单个变身枚举门槛、单个战局赋值及普通草稿；独立合成样本使用探索/返回营地和城内/城外验证复用边界。它不支持通用 Operation、动作数组或后台触发。

源码重新核对明确了两点差异：原 JS 先填入草稿，再异步写最新 MVU 状态，写入失败时保留草稿；Player 改为原子保存。原草稿强调 CG 式后续并自称最高指令，手工夹具改用中性的战败后续表述，仍作为普通用户草稿，不提升 Prompt 角色或权限。此处不宣称后续演出或措辞等价。

已验证的本地行为：

- 预览、取消不改变记录；未变身、存在其他草稿、回复尚未完成均不能提交；确认时状态、正文、候选或草稿变化会拒绝过期预览。
- 原子保存只改变目标枚举、当前候选的后置状态和草稿，保留原回复及其他候选；落盘失败时不发布事实或草稿；同一确认凭据不能重复执行。
- 选择记录随候选保存，真正重新创建磁盘仓库后仍存在；生成失败与重试不会重复选择。
