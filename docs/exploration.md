## 当前要回答的问题

Tavern Player 想消费 SillyTavern 社区已经形成的角色卡、世界书、Regex、Preset 和其他约定，同时不把这些复杂概念全部暴露给玩家。

当前探索只需要帮助我们判断一件事：

> 能否把真实社区内容收敛成一个可维护的播放器运行时，并让用户仍然只需选择角色、Preset 和模型，然后聊天？

## 可以尝试的最小切片

一种可能的观察路径是：

```text
一份真实或接近真实的社区内容
  -> 读取其中与本次实验有关的信息
  -> 形成可观察的模型输入
  -> 接收一个真实或模拟的模型输出
  -> 执行必要的后处理
  -> 得到用户看到的消息
```

这只是帮助发现问题的切片示意，不规定数据结构、模块划分、实现顺序、Provider、fixture 数量、测试形式或界面范围。任何步骤都可以根据实际发现被替换、合并、拆开或跳过。

fixture、诊断、snapshot 和自动化测试可以在它们有助于理解行为或防止回归时加入，不作为探索开始或结束的前置条件。

## 放弃条件

> 如果实际探索表明，兼容 SillyTavern 内容所需的复杂度无法收敛成一个可维护的播放器运行时，或者必须重新实现大部分 SillyTavern 才能提供可接受的体验，就停止当前路线，重新评估产品前提。

可能提示这一问题的现象包括：核心语义长期无法稳定解释、最小有用兼容范围持续膨胀，或者兼容成本已经压倒简单播放器带来的产品价值。这些是观察信号，不是独立的验收项。

除这个放弃条件外，本文不设置阶段门、固定工时、必交物或通过清单。一次探索何时已经提供足够信息，以及接下来做什么，由项目开发者结合实际情况决定。
