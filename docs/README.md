## 维护约定

- 持续变化的产品边界与实现信息更新现有入口，避免每次小改动再增加一份并列的“当前”文档。
- 新的长期格式或上游语义参考放入 `reference/`；阶段方案、实验和验收记录放入 `archive/`，写清日期、版本、成功与失败范围。
- 有独立决策价值的在讨论方案可暂留 `docs/` 顶层；被吸收或替代后更新索引并归档。
- 移动文件同步修改相对链接，包括指向源码、夹具和其他 Markdown 的链接；仅改文档时检查链接和 diff，不把旧记录里的测试写成本次已执行验证。
