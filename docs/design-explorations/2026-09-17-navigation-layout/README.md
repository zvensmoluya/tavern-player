# 底部导航、对话列表与角色库布局试验

日期：2026-09-17。状态：探索参考。四项底栏、全局对话列表和角色双视图已接入首版代码；图片不是效果验收稿。

![对话列表布局概念图](conversation-list-concept.png)

## 本次讨论确定的方向

- 底部四个入口按「对话｜角色｜模型｜我的」排列。
- 对话页汇总所有角色的聊天记录，每场独立对话单独一项，不按角色折叠；点击直接续聊。
- 模型作为独立功能区域；预设管理入口归入「我的」，聊天内保留预设快捷入口。

## 角色库：保留两种视图

角色页提供「两列封面」与「单列名册」两种布局，默认两列，在页面顶部提供视图切换按钮，并记住用户上次的选择。这个偏好只影响角色页，对话页保持单列。

两种布局共用角色数据、搜索条件与排序，点击角色都进入同一个详情页；不是两套独立功能。概念图尚未画出视图切换按钮，首版已将切换按钮放在顶部搜索与导入入口之间。

## 图片的使用边界

这些 AI 生成图仅用于试验布局和信息层级，**没有确认纸质童话风或任一图的视觉处理为后续统一视觉风格**。配色、纸纹、字体、插画、装饰和控件造型均未定稿，不应以这些图约束其他页面。角色双视图已实现，具体间距、卡片比例和视觉处理仍可继续调整。

角色头像、名字、简介、故事标题和消息均为概念占位内容；首版实际使用原卡标签，再回退到作者或「查看角色详情」，不生成或编造简介。角色名字/标签搜索已实现；图中的故事标题、对话搜索及装饰文案不代表已实现，其中对话搜索、对话命名尚未作出新增决定。实际行高、摘要信息量和底栏尺寸仍需布局验证。

对话图保留的是修正透底观感后的版本，角色图保留两列与单列两个方案，供讨论参考，不作为应用运行时资源。后续首版实现的行为边界见[实现架构](../../architecture.md#首页布局与导航状态)，仍不要求统一成图中风格。
