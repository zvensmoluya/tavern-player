# 世界书运行语义：差异分类与待办

2026-09-07 源码核对记录。用户决定先记录、后续解决；本次不修改运行逻辑或世界书界面入口。

> 2026-09-08 后续：用户已要求推进世界书阅读与明确的编排修正。扫描范围、delay 和逐轮筛选等实现变更见[本轮记录](world-book-reader-and-semantics-20260908.md)。下方“当前行为”和延期决定描述的是 09-07 审计时状态。

## 产品决定

世界书继续属于角色卡，当前入口偏深的问题暂缓处理。目标是优化 Player 的体验，不追求完整复刻 ST。但资源组织方式的简化，不应被用来解释对作者显式字段的错误执行。

保留已经确定的产品边界，修正已支持能力中的语义错误，对暂不支持的能力明确给出诊断。若主动改变作者设置的含义，应另行记录理由、用户可见行为和验证证据，不把未审查的实现差异追认为优化。

## 对照范围与证据

- 本机 ST 源码基线：提交 `8172dcd0e`（2026-07-07），`public/scripts/world-info.js` 的扫描缓冲、`#checkDelayEffect`、`checkWorldInfo` 和导入字段映射。
- 辅助说明：[ST World Info 官方文档](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)。在线文档可能随版本变化，后续回归应固定源码基线。

本次仅进行源码对照，未运行 ST 与 Player 的相同输入差分测试。以下描述是已识别的实现差异及其可能影响，不代表已有整卡实测证明所有问题都会出现。

## 差异分类

| 项目 | 当前行为与影响 | 分类及后续处理 |
| --- | --- | --- |
| 世界书来源 | 由角色决定参与的世界书，不组合 ST 的全局、Persona、聊天来源 | 明确产品取舍，保留；卡外资料不自动带入 |
| 缺省设置 | 未指定时扫描深度 2、总世界书预算为有效输入预算的 25%、递归关闭；不继承用户在 ST 中的全局设置 | 默认策略选择，不直接判为 bug；后续核对可解释性及显式字段优先级 |
| 扫描角色字段 | Player 总把描述、性格、场景、深度提示、作者备注加入扫描；ST 按条目的对应匹配开关加入 | Bug 级别语义差异。设定中出现的词可能反复触发条目；应按受支持的显式开关构建扫描输入 |
| `delay` | Player 首次匹配后启动倒计时；ST 在聊天消息数小于 `delay` 时抑制激活 | Bug 级别语义差异。把开局消息门槛变成首次命中后的等待；需校准消息计数及历史恢复行为 |
| 递归与分组 | Player 先收集递归候选，再做分组和预算；ST 在每轮扫描内处理分组、概率、预算和递归推进 | 逻辑缺陷。最终分组落选的内容可能已触发其他条目；需验证组合顺序，不能仅交换函数而忽略概率与预算 |
| 高级正则与扫描格式 | Player 使用 Java Pattern，支持的 flags 有限；扫描文本未完整保留 ST 的消息分隔及发言者格式 | 兼容能力缺口；明确诊断支持边界。普通词匹配通过不证明高级 JS 正则等价 |
| 数字递归延迟层级 | 导入目前按 Boolean 读取 `delay_until_recursion`，未完整接入 ST 的数字层级 | 兼容能力缺口；决定支持范围，避免静默丢失或改义 |

## 后续验证任务

1. 优先修正扫描范围、`delay` 和递归分组隔离；无需为此引入 ST 的多来源世界书体系。
2. 使用中性合成夹具，覆盖匹配开关开／关、仅角色设定命中、聊天消息门槛前／后、首次命中发生在门槛之后、分组落选条目不能触发后继条目。
3. 固定随机输入并检查分组、概率、预算、递归的组合；额外核对宏展开前后内容与预算溢出对递归的影响，不先假定这些顺序已经等价。
4. 检查 sticky、cooldown、重试、候选切换和历史恢复，避免修复 `delay` 时破坏现有状态事务。
5. 对高级正则、数字递归层级明确支持或诊断，再以真实卡验证；不按单卡新增专用规则。

MVU／EJS 的执行支持不能代替本项校准：世界书引擎仍决定模板何时获得执行机会。现有本地功能测试证明实现中的若干行为，不能作为 ST 语义等价证明。
