## v4 历史设计：保留程序，让模型理解行为

固定现有 Player 能力，不扩建脚本、事件、表达式或通用动作 Runtime。远程图片延期，编译不生成关系分析或记忆流程。原卡与已有对话快照保持不变；普通表单生成可编辑草稿，不自动发送。

先前 v3 在本地识别特定 Zod、jQuery 表单和单变量 getvar 分支，然后让模型选择候选。这实际上把语义理解前移到了受限识别器，无法处理同一行为的不同程序写法，也会在模型看到内容前丢失信息。v4 删除 NativeProgramSyntax、NativeProgramForms 及旧候选契约，不保留其兼容路径。

流程改为：

    不可变角色卡
      → 本地按来源整理 JS、HTML、正则、EJS、变量与协议规则
      → 适配模型理解数据流和可观察行为，生成现有 Native 能力的配置
      → 本地恢复原文引用、模板和严格数值边界
      → 既有 NativeAdaptationValidator 校验
      → 安装 → 新对话快照

模型输出现在包括状态定义与初值、协议映射、控件定义、阶段和原文块关系，而非只选择预先识别的候选。输出契约从 Kotlin 序列化描述生成，模型仍无权设计新运行时。

## 原卡的协作链

状态卡通常把程序分散在不同来源中：

1. 世界书的自然语言更新规则告诉聊天模型何时、如何改变变量。
2. 宏和 EJS 读取当前变量与聊天记录，构造本轮 Prompt。
3. 聊天模型生成剧情与机器可读更新块。
4. MVU 等扩展处理更新块，保存消息对应的变量；Schema 或事件回调可补充确定性处理。
5. 显示正则替换标记、折叠机器文本；界面 JS 读取变量并响应交互。
6. Prompt-only 正则控制哪些历史文本再次进入聊天模型。

不是所有卡都有全部环节，也不能把上述关系视为所有扩展版本固定的回调顺序。参考 [SillyTavern Regex](https://github.com/SillyTavern/SillyTavern-Docs/blob/main/extensions/Regex.md)、[MVU 教程](https://github.com/MagicalAstrogy/MagVarUpdate/blob/beta/doc/tutorial.md)、[Prompt Template](https://github.com/zonde306/ST-Prompt-Template/blob/main/docs/features.md)。这些资料用于说明职责，不能替代对卡片引用依赖版本的核对。

## 请求内容与过滤边界

- 完整发送卡内 Tavern Helper 脚本，包括字符串、注释、正则字面量、导入路径、循环和未知调用；保留脚本启用状态及所属目录状态。
- 完整发送显示/提示词正则配置及替换 HTML/CSS/JS，不先提取表单或状态栏候选。关闭的代码仍可审查，但不会作为已启用入口。
- 世界书中的 EJS 保留原始代码，用本地 ID 标记代码间的全部原文块，包括公共前后文和空白。不根据条件写法筛选。分隔符不明确时保留该条混合文本，不删掉未知程序。
- 发送带初始化、变量、规则、输出格式标记的相关世界书、含程序宏或协议标签的正文，以及卡内扩展变量数据。静态世界书提供来源索引和元数据。
- 角色描述、开场等字段若嵌入程序，则保留该字段的完整混合文本；单纯 user/char 名称占位符不会触发上传整个叙事字段。
- 普通静态背景与无程序标记的开场留在本地，不读取当前聊天记录、用户连接凭据，也不把已安装适配或人工答案放入请求。JS 内原有文案和模板正文属于本轮明确提供给模型的源码。
- 标题/标记过滤可能漏掉藏在普通叙事中的自然语言规则；未知扩展字段只报告来源。这是输入覆盖限制，不能宣称预处理已经完成完整语义审计。
- 远程 import 的路径完整可见，但不自动下载、执行或假定其精确实现。请求提供已核对的宿主职责概述，并明确依赖版本未验证。

输入上限 256,000 UTF-16 单元，输出上限 131,072；超限拒绝，不静默截断。模型上下文默认产品预算 128K，输出最多预留 16,384 tokens，仍执行服务端协议适配层的 token 预算检查。这些不是模型规格声明。

## 本地工作与校验的实际含义

模型通过稳定 sourceId、textRef 指向来源。本地根据原件生成 SHA-256、UTF-16 区间和安装绑定；不让模型抄写长篇分支正文。世界书选择必须保留该来源全部非空原文块，不能漏掉公共规则。模型负责判断条件是否真的能由现有数值阶段或枚举选择表达；本地引用检查不证明这个语义判断正确。

普通草稿表单目前通过原 JS 模板字符串的精确唯一前锚点与后锚点定位原文。模型给出完整插值与字段映射，程序进行替换和字面量转义解码，不解释 JavaScript。字段、默认值、多选 join 和空值语义由模型根据完整源码判断。非模板字符串构造、不可表达的插值或不同连接方式仍须报告缺口；源程序仍完整提供，不会因不支持输出而从输入消失。

模型选择严格大于边界时，用 exclusive=true 声明；程序通过 binary64 nextUp 产生实际阈值，避免把 >0 近似为 >=1。阶段含义与条件关系仍由模型负责。

NativeAdaptationValidator 继续校验状态类型、ID、范围、标量协议路径、固定 View 引用、来源哈希和资源预算。模型评估的 targets 必须指向实际适配结果；无映射的还原声明降为不确定。报告保留未评估来源、输入遗漏与动态集合限制，当前自动编译结果固定为 PARTIAL；可安装不等于整卡通过验收。

没有增加任意 JS/EJS 执行器，也没有新增运行时 DSL。动态物品增删、历史查询条件、任意事件等无法用当前 Runtime 表达的源行为继续明确报告。已有 Runtime 适配格式不变；v1–v3 编译响应不再兼容 v4。

## 后续真机修正：宏边界正则

首次手机试用发现，Program View 的宏扫描正则没有转义结尾的两个右花括号。桌面 JVM 接受该写法，Android ICU 在构造正则时抛出 PatternSyntaxException（index 13），发生在请求整理阶段，尚未发出网络请求。这是本地兼容性缺陷，不能归因为服务端传输失败。

已显式转义宏边界，并增加 NativeCompilationAndroidTest：实际 C-03 原件的完整预处理，以及身份宏隔离、变量宏识别、EJS 分块和本地完成流程。测试不联网，不读取或修改现有角色库和对话。

在同一台实体手机上，先安装新增测试 APK 对旧生产 APK 执行：2 项均复现相同异常；随后保留数据覆盖安装修复版，再执行相同测试：OK (2 tests)。应用重新启动成功。真实模型编译没有在这次回归中重发。

本轮运行 :content-core:test、:app:assembleDebug、:app:assembleDebugAndroidTest，通过；真机使用 AndroidJUnitRunner 定向运行上述测试类。修复前后记录保存在忽略目录 app/build/native-compiler-android-before-fix.txt 与 native-compiler-android-after-fix.txt。此前的桌面测试和应用启动检查未覆盖 Android 正则差异，新增真机测试用于防止同一入口再次漏检。
