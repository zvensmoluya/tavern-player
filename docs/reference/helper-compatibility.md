# 酒馆助手兼容能力与实现顺序

更新：2026-09-10。本文记录已确定的推进方式、目标归属及交付门槛，不宣称这些能力已实现。生产现状仍由 [网页运行契约](../web-runtime.md)维护。

## 1. 交付对象

Player 消费作者原程序。浏览器执行页面、计算、闭包、对象及回调；兼容接口把宿主业务调用交给 Player。不是识别每段源码的意图后翻译为原生代码，也不是移植酒馆助手的 Vue 管理面板或 ST 服务端。

以能力域为交付单位：一起完成入口、参数、默认值、返回类型、作用域、事件顺序、保存、失败和恢复。接口被注册不等于兼容，一个样本无报错不等于能力域交付。样本用于覆盖真实用法，不能用于缩小已选择接口的语义。

安全边界守在模型凭据、原生入口和目标会话/资产归属。当前对话内的作者程序可以共享运行环境和正常业务能力，不再把“不同作者页面不得共享对象”作为兼容设计前提。不开放任意 Android 对象、文件树或模型凭据；这与实现世界书编辑、变量作用域没有冲突。

## 2. 可复查的契约清单

- [能力域登记](../../tools/web-runtime/compatibility-domains.json)：15 个能力域、目标归属、现状及交付批次。
- [逐项清单](../../tools/web-runtime/compatibility-catalog.json)：全部 31 份非聚合声明文件，402 个声明/导出对象成员；另列聚合声明的 134 个条目、运行注册的 155 个条目和 iframe 绑定的 34 个条目。这些集合有重叠，且含常量/字段，不能相加为 API 数量。
- 每项记录来源，源码记录内容哈希；参照本地助手提交 `dd8327d437eb0cdbd1eddc23b5491812870aa7d8`。小版本变化可直接审阅并更新，不要求为了版本差异暂停开发。
- `binding-present` 只表示 Player 存在绑定；`rejecting-stub` 表示主动抛错占位；`absent` 表示清点的宿主未提供该名称。都不是完整语义验证结果。父页面单独注入的 `TavernHelper` 另标 `installed-by-parent`。
- 类型声明、真实注册及别名分别保留。例如声明 facade 的 `updatelorebookEntriesWith` 与目标函数 `updateLorebookEntriesWith` 不同；不能从文档名称自动推断实际可调用入口。
- `Mvu`、`EjsTemplate`、`SillyTavern` 另列域。助手导出了这些对象的声明，不代表助手自身实现了全部扩展能力。对应实现仍须追溯已登记的公共程序及 ST。

复查入口（参数为本地助手检出目录，不写入本机绝对路径）：

```powershell
cd tools/web-runtime
node audit-contract.mjs <helper-checkout>
node audit-contract.mjs <helper-checkout> --check
```

工具只读取源码、解析声明结构和 Player JS AST，不执行作者或上游程序，不访问网络。新增声明文件若未分配能力域会失败；`--check` 检查清单是否与当前参照源码/宿主一致。它是维护检查，不作为运行时版本限制或兼容率评分。

## 4. 首先改执行语义：会话级作者环境

重构前 `createHost` 每次创建自己的 `listeners`、`initialized` 和变量队列；`parent.mjs` 每个页面各建一个。当前生产路径已改为会话协调器共享这些对象。上游 `predefine.js` 则暴露父页面对象，`global.ts` 发布实际 value，`event.ts` 使用共同 eventSource。两者不只是函数数量不同。

选定的目标是：**每个网页对话有一个持久作者协调 iframe，作者页面仍可拥有独立 DOM/Window，但共享协调器中的对象、事件和操作顺序。** 协调 iframe 与作者内容同源，和可信外壳不同源；它不直接持有原生桥。

```text
Compose / Kotlin 权威业务状态
            ↑ 保存、结果、事实事件
可信消息外壳 / 原生桥
            ↑ 受控消息传递
作者会话协调 iframe（当前对话的作者来源）
            ↕ 同源对象、函数、回调
作者兼容父页面 / 消息页面 / 后台脚本
```

- 使用当前对话唯一来源及运行实例身份，协调 iframe 生命周期独立于消息滚动。作者子页可通过命名 sibling WindowProxy 找到同源协调器；不需要进入可信外壳 DOM。
- `initializeGlobal(name, value)` 保留实际对象、函数和身份；等待操作在对象发布后解除，消息数据就绪等额外条件单独定义。不能把对象传成 JSON 后宣称等价。
- 事件注册表在协调器集中维护，以 frame/script 身份清理监听器。`makeFirst/makeLast` 作用于完整会话事件顺序；`eventEmit` 等待异步监听器，`eventEmitAndWait` 保持上游同步返回。once、重入、异常传播按对应 ST eventSource 实现验证。
- JS 待提交变量视图和宿主写队列收敛到会话级，避免多个页面各自乐观修改后互相产生过期版本。原生仍验证身份、候选和版本，保存后确认。
- 销毁页面注销它拥有的回调和操作入口，保留会话级状态；销毁会话使旧运行实例全部失效。JS 闭包不序列化，恢复时重新加载并注入已保存状态。
- 同一对话作者页面相互可见是有意选择。`script` 作用域表达数据归属，不宣称在同源作者程序间构成安全隔离。

架构证明 `test/browser/session-contract.test.mjs` 已在真实 Edge 验证：两个作者 frame 共享含方法的同一对象，跨 frame 回调同步修改同一参数，注销并移除页面后不再调用旧监听器，作者无法读取不同源的可信桥。生产 `parent.mjs` 现已接入协调器，并通过另一个生产网页集成测试验证多页面、事件只分发一次、清理及预设切换。Android 测试已编译、尚无设备执行；完整 Context/事件集合/脚本管理/provider 仍未完成，A 不能整体标成完成。

## 5. 状态与保存归属

以下是接口实现必须遵循的设计，尚未创建这些新增存储：

| 对象 | 所有者与持久化 | 关键规则 |
| --- | --- | --- |
| JS 全局对象、函数、事件监听器 | 作者会话协调器内存 | 不混同持久变量；退出后重建，不保存闭包 |
| 消息变量/MVU 检查点 | 对应消息候选 | 切候选跟随选中分支；不能把最新候选的数据广播成所有楼层的数据 |
| chat 变量 | Conversation 状态 | 保持当前项目候选检查点规则，并记录与上游聊天元数据的差异 |
| script 数据 | 程序身份对应的已保存状态，导入 data 为初值 | 空对象是实际值；重载不覆盖已保存值；不得用 DOM 可见性决定寿命 |
| character 变量/定义 | 当前对话的 CharacterSnapshot；显式资产操作才修改资产仓库 | 这是 Player 已有快照决策，与 ST 共享角色资产语义有差别；不能静默把所有名称都解释成 current |
| preset 变量/配置 | 预设仓库及其身份 | 当前生成使用已捕获配置，修改影响下一次捕获；不复制成无关的 chat 变量 |
| global 变量 | 若纳入实现，提供真正应用级专用存储 | 当前不存在；不能把 chat 别名当 global，不能任意把已有值当空 |
| 世界书定义及绑定 | 当前快照/会话引用；显式资产操作使用仓库 | 区分改条目和改引用，保留稳定书名及 UID 映射；所有变更进入实际 Prompt |
| Regex 定义 | 角色快照或预设配置的所属层 | 变更同时影响相应 Display/Prompt 投影，不修改原始正文来模拟显示效果 |
| 一次生成、注入、取消 | 原生生成事务；浏览器保存函数钩子 | 开始时捕获配置和有效注入；结束/停止按规则撤销 once；恢复不自动重发请求 |

每个写接口需明确它是运行状态写入还是资产编辑；保存完成、事件和 UI 更新的关系按接口的同步/异步契约定义。不得把“一律 Promise”或“一律同步返回成功”作为统一桥接简化。

## 6. MVU/EJS 的唯一执行归属

QuickJS 是实现选择，不是所有网页卡必须迁入的引擎。网页模式允许原扩展留在浏览器，尤其当它需要 DOM、共享对象或同步回调时。已有独立 QuickJS 路径可以保留，但只能作为整个已验证程序的 provider，不能依靠拆散任意作者程序维持两个引擎。

provider 契约需记录程序来源/依赖、初始化入口、事件订阅、更新入口、状态提交和销毁。一次对话内，同一 MVU 更新只允许一个 provider 执行：

1. 使用原浏览器 provider 时，Kotlin 不再主动执行另一份 MVU 初始化/更新。
2. 使用已验证 QuickJS provider 时，它对应的原浏览器启动入口不再执行，由 facade 提供已验证接口。
3. 未识别依赖不能声称已去重；在可完整托管之前明确展示未覆盖的归属问题。不能根据有限正则猜测安全拆分，也不能继续把混合作者脚本停用当成最终兼容方案。

EJS 亦按完整功能选择 provider。当前登记世界书只读求值只是其中一个 profile；完整扩展还有 prepareContext、allVariables、render/generate loader、注入与可写状态。若要让它们共享浏览器对象，应从 Prompt 编译器提供异步求值/钩子边界，再回到同一生成事务。不得同时运行模板预求值与另一份扩展钩子处理同一内容。

## 7. 按依赖顺序交付

```text
A 会话作者环境 / 事件 / 初始化 / 生命周期
  └─ B 变量作用域 / 消息候选 / 保存恢复
       └─ C 世界书 / Regex / Macro / 投影
            └─ D 生成钩子 / 注入 / MVU与EJS完整provider
E 资产接口按 B–D 所需仓库逐步接入；F 独立按产品价值安排。
```

| 批次 | 必须一起交付 | 出口验证 |
| --- | --- | --- |
| A | 协调器接入生产外壳；共享对象；完整事件队列；脚本启停和身份；Context 最小 facade；唯一 provider 注册规则 | 双页面共享对象与同步回调；监听顺序/once/重入/异常；页面销毁与预设切换；Android 生产 WebView 桥；证明确实只有一个更新执行者 |
| B | 选定变量作用域全部读写辅助函数；候选/楼层映射；消息 CRUD/移动；显示刷新；同一提交路径 | 负索引/范围/隐藏/候选；连续跨页面写后读；回调结果类型；保存失败；切候选与进程恢复；与参照行为对照 |
| C | 世界书读写、条目 CRUD 与绑定；旧接口转换；Regex 读写和格式化；Macro 回调接入 | 写后 Prompt 内容实际改变；Display/Prompt 分离；UID 稳定；删除/重建/恢复；异步回调与同步格式化的明确实现边界 |
| D | 生成参数映射；prepare/stream/end/stop 钩子；注入及清理；选定 MVU/EJS provider | 同一回复只更新一次；初始化先于依赖求值；停止不重发；流式事件载荷；失败与恢复；完整原卡从开场到下一轮状态变化 |
| E | 实际需要的角色/预设/身份/导入接口，复用现有仓库 | 导入导出、捕获快照、生效时机、名称/身份错误，不引入另一份资产数据库 |
| F | 音频、辅助管理、能力查询等独立功能 | 对应功能本身的行为测试；不以版本号冒充完整扩展 |

A/B/C/D 不以“所有接口函数存在”作为结束条件。每组必须记录声明、参照实现、Player 实现、语义差异和验证证据；没有跑到的条件保留为未验证。发现更底层缺口时修正对应能力域，而非给样本分支打补丁。

C 的世界书部分已按本表前四项出口验证交付，证据见[网页运行契约](../web-runtime.md)；世界书设置接口、全局与聊天文件作用域保留为兼容缺口，Regex 的格式化与 Macro 回调仍未接。

## 8. 已知的系统性差异与验收材料

首次核查已发现，应归入对应批次处理：

- A：initializeGlobal 的 value 和会话事件顺序已由生产协调器解决；SillyTavern Context、完整事件集合、脚本管理与 provider 仍未接齐；跨引擎闭包不能序列化模拟。
- B：消息范围已对齐端点截断及排序，结构操作及候选数组已接入；角色变量独立于 chat 检查点。预设/global 等变量归属、Schema UI 和完整消息事件仍需交付。
- C：上游世界书新旧接口有不同结构和命名，Regex 格式化还串联 Macro/自定义回调；不能把引擎已有等同于助手接口已经具备。本轮已把新旧两种条目形状接到同一份会话快照定义上；条目 `filters` 与 `automation_id` 仍明确拒绝，世界书引擎设置没有全局宿主，因此不提供。
- D：上游 injectPrompts 的 filter 可以是函数且返回撤销入口，不能直接 JSON 化；原生只读 EJS 不覆盖完整模板扩展。

材料按契约选择：合成夹具负责边界条件和事件序列；中性原卡样本负责真实组合；MVU/EJS 公共程序负责扩展行为对照。C-05 简单表单只覆盖父输入回写；四份复杂原件已加入浏览器交互与原生初始化/状态回复/后续编排测试。确定性回复不替代真实模型或设备验收。未改原卡、零导入编译模型调用仍是基础游玩目标。

清单与架构证明之后，A 的生产协调器、共享对象、初始化、事件、共享队列及销毁清理已落地，验证见[网页运行契约](../web-runtime.md)。尚未完成 A 的剩余接口及设备验收，不将它们计为通过，也不以此宣称整卡兼容。
