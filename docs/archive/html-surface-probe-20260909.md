# HTML Surface 探针复核（2026-09-09）

> 状态：阶段调查已结束，保留为验证证据；探针暂停扩建。兼容工作以扩展公开契约与实现为依据，卡片只用于选取验收场景。已修复记录器并重新采样。这里只描述桌面浏览器在**指定模拟宿主与资源限制下**执行的路径，不是 Player 已实现能力或完整兼容接口清单。
> 工具与复现命令见 [card-probe](../../tools/card-probe/README.md)，路线背景见[HTML Surface 讨论](../html-surface-discussion-20260909.md)。

## 复核结论

探针可用于发现下一步需要核对的依赖，但旧报告“22 个展示面只需要 9 个接口”“宿主面小一个数量级”的结论撤回。当前观察不能估计整个生态的接口规模，也不能比较两条路线的投入比例。

更有用的结果是：S-02 的原开场页面在点击后请求修改消息候选；其状态页面在事件触发后重新读取 MVU。C-03 的开局表单则直接依赖父页面输入框，无法只靠消息 API 对齐运行。

## 旧工具的问题与修复

- `bind/call/apply` 原来绑定空函数，绕过 Proxy 的调用记录与返回值；现已绑定代理本身，测试覆盖直接、绑定、call 和 apply 四条路径。
- 事件注册原来不保存回调，`--fire` 只设置标志而没有触发功能；现在以场景步骤明确触发事件，记录加载、事件、点击等不同阶段。
- 宿主有可控的模拟变量和消息数据；初始化等待可保持挂起直到测试显式初始化。它们不是 ST 的完整语义实现。
- 调查原来扫描整个旧提取目录，失败项未进入汇总。现在只使用本轮提取清单，按运行 ID 独立保存，失败也占一行，旧日志不参与本轮汇总。
- 记录器未就绪不再返回空列表冒充零调用。输出记录页面异常、console 错误、资源阻断、未实现调用、等待中的全局初始化和日志截断数。
- 原来的 DNS 拦截不能证明全部网络被阻断，也不能证明资源失败不影响调用路径。新版在导航前安装 CDP 拦截、提供固定本地页面与库，配合 CSP 限制外部资源；不再开放文件读取或关闭 Chromium sandbox。仍不把这套调查配置视为经过安全验收的通用运行时。

## 定向交互：原开场与单条展示 Regex

这部分从原卡读取开场正文，校验所选 Regex 未停用、为展示规则且匹配正文，使用原始替换模板生成页面。没有修改作者代码，但也没有实现完整 ST/Player 的多规则排序、Macro、Markdown 和生命周期链路。

### S-02：点击后出现消息写入请求

输入为原 `first_mes`，使用 `regex[4]`（候选索引 1）。页面先调用 `getCurrentMessageId` 和 `getChatMessages`；点击第一张开局选择项后调用：

```javascript
setChatMessages([{ "message_id": 0, "swipe_id": 1 }])
```

模拟消息快照随后含 `swipe_id: 1`。这证明该点击路径要求写消息候选，不证明 Player 已切换开局正文、保存状态或能在重启后恢复。

### S-02：变量事件触发重新读取

输入为原 `alternate_greetings[5]`，使用 `regex[6]`（候选索引 3）。页面等待模拟 MVU 初始化，注册 `Mvu.events.VARIABLE_INITIALIZED` 与 `Mvu.events.VARIABLE_UPDATE_ENDED`，并在加载时读取一次数据。

测试把模拟 `stat_data` 改为含 `probe_counter: 7` 的数据，分别触发两个事件；两次回调均重新调用 `getCurrentMessageId` 与 `Mvu.getMvuData`。这验证了回调路径可执行，未验证作者完整状态树、字段显示正确性、真实 MVU 初始化顺序或事件参数契约。

### C-03：直接依赖父页面 DOM

输入为原 `first_mes`，使用 `regex[0]`。填写测试名称并点击确认后，作者程序直接查找 `window.parent.document` 中的 `#send_textarea`，打算写入草稿并派发 input 事件。

独立页面没有该输入框，程序记录相关 console 错误并调用 `toastr.error`；没有观察到消息 API 写入。这里的缺口是**对源宿主 DOM 的耦合**。后续应明确是否提供受限的父页面兼容结构或将该行为列为不支持，不能默认为现有原生方法已经覆盖。

C-04 还包含指向 localhost 开发服务器的候选模板，但该规则在原卡中已停用。它说明候选扫描会收集未启用内容，不能直接认定这张卡的实际运行必需该服务器。

## 对下一步的影响

下一步直接固定 Tavern Helper、MVU、EJS 的版本，研究其公开接口、实现及对 ST 的依赖，再与 Player 已有能力对照。参数、返回值、状态归属和事件顺序由扩展契约与实现确定，不从本次模拟调用统计反推。卡片用于验收已选择的兼容能力；探针仅在具体动态路径存在疑问时辅助验证，不作为接入前置工程。

未覆盖真实 Tavern Helper/MVU 后台程序、所有交互分支、远程模块加载、生成中断、候选恢复、进程恢复、Android WebView 或设备性能。本轮只修改调查工具和记录，没有接入应用代码，也没有调用模型 API。
