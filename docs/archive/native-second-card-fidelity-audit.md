## 已核对的边界

RUBY 的活动方案优先于外层遗留 `tasks` 字段。不能把外层旧的第十轮“心理闪回与记忆分析”配置误报成当前活动行为。脚本从已激活方案取得任务、引用池和开局任务；本卡方案的开局任务关闭，三项周期任务启用。

源分析依赖宿主插件、来源提示条目及可用模型连接。这里记录的是代码与配置声明的行为，并未启动原宿主插件验证其网络或调度。源提示中的越权语句只作为惰性原件保留，不成为 Player 权限规则，也不授权使用源文件内的第三方连接。

S04 已复用原文引用机制并扩展固定公共前后文，经过完整实际 Prompt 检查。S09–S12 需要单独评估 Player 拥有的长期上下文分析流程；它不能由一组任意 Trigger/Action 或执行源 JS 来代替。已有阶段机制能覆盖 S03，但尚不足以证明整个第二样本可还原。

## Player 原生关系分析实验与明确差异

已接入三个受限原生分析定义：第 5/10/15 个助手条目起，每 15 个助手条目刷新对应记忆；开场计入，与所审源码计数方向一致。每项引用原 id 10/11/12 的完整分析要求，并读取自己的上次结果。运行及保存语义见 [对话记忆](adaptation-runtime-v1.md#对话记忆)。自动刷新、详情中的手动刷新/重试和只读查看均已接入应用。

**资料别名存在歧义。** 世界书 id 0/1/9 都含角色 A 的同组别名 key，id 2/3 都含角色 B 的同组别名 key。源脚本先调用宿主 findentry，再检查返回条目的 key；当前尚未运行原宿主证明它会返回哪份同名资料。本轮手工适配明确绑定通用人物资料 id 0、2，并对指向同一资料的别名去重；没有把 NSFW 或后期关系专属条目冒充确定的原运行结果。这是本实验明确采用的人工选择，不能宣称参考池完全等价；不再把运行原宿主确认别名查找作为本实验的前置条件。

此外，Player 不复刻外部小白X摘要缓存与其最后处理位置，当前分析读取完整选中路径；不执行源清理正则，采用 Player 已存正文。结果使用专用记忆层参与 Prompt，未向可编辑源 World Book 写文件；条目常驻、角色前，字面文本可参与关键词扫描但不执行宏或正则。它也没有复制源输出 key、selective/recursion 等任意可配置表单。这些差异必须结合实际语义判断，不是自动视作视觉降级。

本地测试覆盖来源校验、周期/失败条目/手动刷新、分析证据、保存往返、过时结果拒绝、候选隔离、历史文本编辑失效、取消后正文保留、手动重试不新增聊天条目、输入草稿不丢失，以及下一轮 Prompt 的记忆和关键词作用。测试发现了记忆在 Prompt 组装阶段被二次宏展开的问题，已改为独立字面注入并确认 setvar 字符串不会修改本地变量。
